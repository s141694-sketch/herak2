# حراك 2 — دليل المجموعة الذهبية وتقييم الوكلاء

| البند | القيمة |
|---|---|
| التاريخ | 2026-10-03 |
| المرجع | المواصفة 5.5 و8.2، خطة المرحلة 4 (المهمة 4.5)، القرارات D40 وD41 |
| لمن | المالك وخبراء التخصص الذين يبنون المجموعة الذهبية |

## 1. لماذا

لا يعمل أي وكيل ذكاء اصطناعي لأي مؤسسة قبل أن يجتاز حد الدقة الذي يحدده المالك على المجموعة الذهبية (المواصفة 5.5). البوابة مغلقة الآن لأن المجموعة والحدود لم تُحدَّد بعد، والمنتج يعمل بالقواعد فقط حتى ذلك الحين.

## 2. ما يفعله الخبراء

1. يأخذ كل خبير ملف CSV فيه البنود (أهداف، أو أزواج هدف وكفاية، حسب الوكيل).
2. يصنّف كل بند بنفسه دون الاطلاع على تصنيف زملائه.
3. تُجمع الملفات في ملف واحد، صف لكل (بند، خبير).
4. عند الخلاف يمكن إضافة صف باسم الخبير `adjudicator` يحسم التصنيف المعتمد.

## 3. صيغة الملف

| العمود | المعنى |
|---|---|
| `item_key` | معرّف ثابت للبند (مثل `o-017`) |
| أعمدة المدخل | تختلف حسب الوكيل (مثل `objective`)، ويجب أن تتطابق في كل صفوف البند |
| `expert` | اسم الخبير أو رمزه |
| `label` | التصنيف من القائمة المسموحة للوكيل |

التصنيف المعتمد لكل بند: تصنيف `adjudicator` إن وُجد، وإلا الأكثر تكرارًا. التعادل يترك البند بلا تصنيف معتمد: يُحسب في اتفاق الخبراء ولا يدخل في دقة الوكيل.

قوالب الملفات في `evals/templates/`:

| الوكيل | الملف | التصنيفات المسموحة |
|---|---|---|
| `classification` | `classification.csv` | `cognitive:1`…`cognitive:6`، `affective:1`…`affective:5`، `psychomotor:1`…`psychomotor:7`، `unclear` |
| `alignment` | `alignment.csv` | `aligned`، `weak`، `misaligned` |
| `alignment_suggestion` | `alignment_suggestion.csv` | `ok` للكفاية التي يمكن كتابة هدف سليم لها |
| `drafting_rewrite` | `drafting_rewrite.csv` | `ok` للهدف الضعيف الذي يمكن إعادة صياغته صياغة سليمة؛ عمود `competencies` اختياري، كفاية في كل سطر بصيغة `الرمز: العنوان` |
| `drafting_outline` | `drafting_outline.csv` | `ok` للبرنامج الذي يمكن بناء هيكل مبدئي له؛ `levels` أسماء مستويات القالب من الأعلى مفصولة بـ `/`، و`competencies` كفاية في كل سطر بصيغة `الرمز: العنوان` |
| `import` | `import.csv` | `ok` للنص الذي يمكن توزيعه توزيعًا سليمًا؛ `text` نص المنهج كاملًا (في خلية واحدة بين علامتي تنصيص)، و`levels` أسماء مستويات القالب من الأعلى مفصولة بـ `/` |

المقاييس: `classification` الدقة (accuracy)؛ `alignment` دقة وشمول كشف `misaligned` (precision وrecall) والدقة العامة؛ `alignment_suggestion` نسبة الاقتراحات التي تقبلها قواعد حراك (`well_formed`)، ويُقاس المعنى من قبول المؤلفين ورفضهم أثناء الاستخدام. `drafting_rewrite` نسبة الصياغات التي تقبلها قواعد حراك وتختلف عن الأصل (`well_formed`)؛ `drafting_outline` نسبة الهياكل التي تخدم كل الكفايات المعطاة بأهداف تقبلها القواعد ضمن عمق القالب (`complete`). `import` نسبة التوزيعات الصالحة التي تضع كل أسطر النص (`complete`) ونسبة الصالحة عمومًا (`valid`). حفظ المعنى في هذه الحالات يُقاس من قبول المؤلفين ورفضهم المسجّل. كل وكيل يُضاف قالبه مع بنائه.

## 4. الأوامر (يشغّلها المسؤول التقني)

```
uv run python manage.py evals_import golden.csv --agent classification --name "2026-10 الدفعة الأولى"
uv run python manage.py evals_agreement <رقم المجموعة>
uv run python manage.py evals_threshold classification accuracy 0.85 --note "قرار المالك"
uv run python manage.py evals_run classification
```

- `evals_import` يتحقق من الملف ويرفض الصف الخاطئ برقم سطره، ثم يطبع اتفاق الخبراء.
- `evals_agreement` يطبع نسبة الاتفاق، وكابا كوهين لكل زوج خبراء، وكابا فلايس حين يصنّف كل بند العدد نفسه من الخبراء. هذا هو السقف الواقعي لأي وكيل.
- `evals_threshold` يسجّل حد المالك لمقياس. تغيير الحد يلغي أثر التقييمات السابقة حتى يُعاد التقييم.
- `evals_run` يشغّل نسخة الوكيل الحالية (نسخة التعليمات والنموذج) على أحدث مجموعة ويحفظ النتيجة.

## 5. متى يُطلق الوكيل

يُطلق الوكيل لكل المؤسسات عندما يوجد تقييم ناجح لنسخة تعليماته ونموذجه بالضبط:
- على أحدث مجموعة ذهبية لذلك الوكيل،
- بمزوّد حقيقي (لا تُعد التقييمات بردود مسجّلة أو مزيفة دليلًا)،
- مقابل الحدود الحالية التي سجّلها المالك.

أي تغيير في التعليمات أو النموذج أو المجموعة أو الحدود يغلق البوابة حتى يُعاد التقييم وينجح.

## 6. ما يحتاجه المالك

- حدود الدقة لكل وكيل (المسألة المفتوحة 4).
- حجم المجموعة الذهبية (المسألة المفتوحة 5): نبدأ بعيّنة أولية ونقيس اتفاق الخبراء.
- مفتاح المزوّد في بيئة التشغيل، بعد مراجعة شروط استخدام البيانات (المسألة المفتوحة 3).
