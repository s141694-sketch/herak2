## 1. المعمارية

```
المتصفح (TipTap + Yjs)  ⇄  collab (Hocuspocus)  ⇄  Django
        │  رمز قصير العمر لمستند واحد ←──────────── POST /api/program-versions/{id}/collab-token/
        │                   │ تحميل الحالة أو الصفوف ── GET  /api/internal/collab/documents/{id}/
        │                   │ حفظ الحالة + الصفوف + رقم تسلسلي ── PUT  /api/internal/collab/documents/{id}/
        │                   │ الإبلاغ عن فشل التحويل ── POST /api/internal/collab/documents/{id}/failure/
        │                   ⇠ تجميد قبل الإرسال وإرجاع المستند ── POST /internal/documents/{name}/freeze   (Django ← collab)
        │                   ⇠ فك التجميد إن بقيت مسودة ─────── POST /internal/documents/{name}/unfreeze?token=…
        │                   ⇠ لقطة دون تجميد (المقارنة) ────── POST /internal/documents/{name}/snapshot
        │                   ⇠ قفل بعد الإرسال ───────────────── POST /internal/documents/{name}/lock
```

> **تعديل بعد المراجعة المستقلة (D43):** كان المخطط الأول «تفريغًا» تحفظ فيه خدمة التعاون عبر Django أثناء طلب Django نفسه، وهذا قد يستنفد عمّال Django، وتضيع فيه التعديلات بين التفريغ والقفل. صار Django يطلب «تجميدًا» يعيد المستند نفسه فيخزّنه Django بنفسه، ولا تستدعي أي من نداءات Django خدمةَ التعاون التي تعود إليه.

- **`shared/`**: حزمة TypeScript تعيش في مساحة عمل npm واحدة مع `collab/` و`frontend/` حتى توجد نسخة واحدة من `yjs` (تكرارها يكسر Yjs). تحتوي مخطط المستند، وامتدادات المحرر (مصدر واحد لمخطط ProseMirror)، والتحويل `materialize` / `hydrate`، وتثبيت الملاحظات. كتابة جديدة مستفيدة من `spike/`، مع نقل اختباراته.
- **Django لا يحلل Yjs أبدًا:** يخزن الحالة الثنائية كما هي، ويستقبل الصفوف جاهزة من خدمة التعاون ويتحقق منها.
- **المصادقة الداخلية** بين الخدمتين بسر مشترك في متغير بيئة، ورمز المستخدم JWT موقّع (HS256) بسر آخر، صالح دقيقتين، لمستند واحد.

- D28: مساحة عمل npm واحدة (`shared`، `collab`، `frontend`) لضمان نسخة واحدة من Yjs.
- D29: روابط المواءمة لمسودة حية تعيش في مستند Yjs وتُحوَّل صفوفًا مع العقد والكتل؛ الكفايات المستهدفة تبقى عبر الواجهة البرمجية لأنها لا تشير إلى كتل.

- D43: قبل خروج المسودة من حالتها تُجمَّد وثيقتها الحية وتعيدها خدمة التعاون فيخزّنها Django بنفسه (بدل «التفريغ» الأول)، وكل حفظ يحمل رقمًا تسلسليًا (أُضيف بعد المراجعة المستقلة).

## 4. إغلاق المرحلة (2026-10-03)

- **معيار الإنجاز:** `collab/test/acceptance.test.ts` يشغّل المواصفة 8.1 البند 5 على خدمة التعاون الإنتاجية (`CollabService` مع مخزن يحاكي Django): 2 و3 و4 و5 عملاء بمحتوى عربي، تقارب المستند، الذهاب والإياب دون فقد، ثبات الملاحظة، انقطاع عميل وعودته. يمر.
- **المراجعة المستقلة:** روجع فرق المرحلة في خمسة مجالات (الترحيلات، Django، `shared/`، خدمة التعاون، الواجهة). كل ملاحظة مؤكدة أُعيد إنتاجها أولًا باختبار يفشل قبل الإصلاح، وعولجت في خمسة commits: `f4a325e`، `5685d2f`، `7ba68a0`، `d769663`، `05a33d6`. أكبرها تغيير بروتوكول الحفظ بين Django وخدمة التعاون (D43).
- **التحقق عند الإغلاق:** اختبارات Django كلها، و`shared` (26)، وخدمة التعاون (34)، والواجهة (8)، وPlaywright (12 سيناريو على الخدمات الحقيقية) ناجحة محليًا، وCI ناجح على commits المراجعة.
- **حدود معروفة:**
  1. منع التعديل أثناء التجميد أو القفل يُفرض عند الاتصال وقبل كل رسالة؛ الفحص قبل كل رسالة دفاع إضافي لا يميّزه اختبار، لأن ترتيب التنفيذ في Hocuspocus يجعل الفحص عند الاتصال يسبق الرسائل المؤجلة.
  2. إن عجزت خدمة التعاون نفسها عن تحويل المستند (بنية لا يعرفها المخطط) فلا تُخزَّن حالته؛ يُبلَّغ المحررون، وإن أغلقوه كلهم ضاعت تعديلاته منذ آخر حفظ. أما رفض Django للصفوف فيحفظ الحالة الأحدث.
  3. التجميد الذي لا ينهيه Django يُراجَع بعد دقيقتين: يُقفل المستند إن خرجت النسخة من المسودة، ويُفك إن بقيت. إن تعذّر الوصول إلى Django بقي للقراءة فقط وتكررت المراجعة.
  4. ترتيب الحفظ بالأرقام التسلسلية يفترض ألا تعود ساعة خادم التعاون إلى الوراء بين تشغيلين.
