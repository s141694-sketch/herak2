## 1. المعمارية

```
المتصفح (TipTap + Yjs)  ⇄  collab (Hocuspocus)  ⇄  Django
        │  رمز قصير العمر لمستند واحد ←──────────── POST /api/program-versions/{id}/collab-token/
        │                   │ تحميل الحالة أو الصفوف ── GET  /api/internal/collab/documents/{id}/
        │                   │ حفظ الحالة + الصفوف + رقم تسلسلي ── PUT  /api/internal/collab/documents/{id}/
        │                   │ الإبلاغ عن فشل التحويل ── POST /api/internal/collab/documents/{id}/failure/
        │                   ⇠ تجميد قبل الإرسال وإرجاع المستند ── POST /internal/documents/{name}/freeze   (Django ← collab)
        │                   ⇠ فك التجميد إن بقيت مسودة ─────── POST /internal/documents/{name}/unfreeze?token=…
        │                   ⇠ لقطة دون تجميد (المقارنة) ────── POST /internal/documents/{name}/snapshot
        │                   ⇠ قفل بعد الإرسال ───────────────── POST /internal/documents/{name}/lock
```

> **تعديل بعد المراجعة المستقلة (D43):** كان المخطط الأول «تفريغًا» تحفظ فيه خدمة التعاون عبر Django أثناء طلب Django نفسه، وهذا قد يستنفد عمّال Django، وتضيع فيه التعديلات بين التفريغ والقفل. صار Django يطلب «تجميدًا» يعيد المستند نفسه فيخزّنه Django بنفسه، ولا تستدعي أي من نداءات Django خدمةَ التعاون التي تعود إليه.

- **`shared/`**: حزمة TypeScript تعيش في مساحة عمل npm واحدة مع `collab/` و`frontend/` حتى توجد نسخة واحدة من `yjs` (تكرارها يكسر Yjs). تحتوي مخطط المستند، وامتدادات المحرر (مصدر واحد لمخطط ProseMirror)، والتحويل `materialize` / `hydrate`، وتثبيت الملاحظات. كتابة جديدة مستفيدة من `spike/`، مع نقل اختباراته.
- **Django لا يحلل Yjs أبدًا:** يخزن الحالة الثنائية كما هي، ويستقبل الصفوف جاهزة من خدمة التعاون ويتحقق منها.
- **المصادقة الداخلية** بين الخدمتين بسر مشترك في متغير بيئة، ورمز المستخدم JWT موقّع (HS256) بسر آخر، صالح دقيقتين، لمستند واحد.

## 2. المهام

| # | المهمة | الاختبار / معيار الإنجاز |
|---|---|---|
| 3.1 | `shared/`: مخطط المستند (عقد بعنوان وترتيب، كتل بترتيب ومحتوى XmlFragment، روابط المواءمة)، `materialize` بقاعدة إصلاح الدورات (D4)، `hydrate`، المواضع النسبية للملاحظات والبحث النصي الاحتياطي | اختبارات الوحدة، 1000 مستند عشوائي بالعربية، 3–5 عملاء متزامنين، ثبات الملاحظات |
| 3.2 | رمز قصير العمر من Django بعد التحقق من العضوية والمشاركة؛ collab يتحقق منه ويرفض اسم مستند لا يطابقه؛ القراءة فقط لغير المشاركين أو للنسخ المقفلة | رمز منتهٍ أو لمستند آخر أو بتوقيع خاطئ مرفوض |
| 3.3 | DraftDocument في Django؛ collab يحمّل الحالة أو يبنيها من الصفوف، ويحفظ الحالة والصفوف دوريًا (debounce)؛ Django يطبّق الصفوف بالمفاتيح (upsert) دون كسر الروابط | ذهاب وإياب عبر الخدمتين؛ النسخة الجديدة تنسخ حالة Yjs (D2) |
| 3.4 | لا تعديل على نسخة ليست مسودة: Django يرفض الحفظ، وcollab يقفل المستند بعد الإرسال ويفتحه للقراءة فقط | تحديث بعد القفل لا يصل لأي عميل ولا للصفوف |
| 3.5 | الحضور: مؤشرات بأسماء وألوان، وإظهار من يحرر أي كتلة | اختبار متصفحين: اسم المحرر يظهر على الكتلة عند الآخر |
| 3.6 | الملاحظات بمواقع نسبية، وقسم «ملاحظات بلا موضع» | ملاحظة تبقى على نصها بعد تعديلات متزامنة؛ حذف نصها ينقلها للقسم |
| 3.7 | تعطل collab: المحرر للقراءة فقط مع تنبيه، ثم إعادة اتصال ودمج | Playwright: قطع الاتصال ثم إعادته؛ التعديلات تتقارب |
| 3.8 | فشل التحويل: تبقى آخر صفوف سليمة، تنبيه تقني، ويُمنع الإرسال برسالة واضحة | محتوى غير صالح أو collab غير متاح يمنع الإرسال برمز خطأ |

**معيار إنجاز المرحلة:** المواصفة 8.1 البند 5 على الخدمة الإنتاجية: 2–5 عملاء محاكين بمحتوى عربي، تقارب المستند، الذهاب والإياب دون فقد، ثبات الملاحظات، الانقطاع ثم العودة.

## 3. قرارات جديدة (في سجل القرارات)

- D28: مساحة عمل npm واحدة (`shared`، `collab`، `frontend`) لضمان نسخة واحدة من Yjs.
- D29: روابط المواءمة لمسودة حية تعيش في مستند Yjs وتُحوَّل صفوفًا مع العقد والكتل؛ الكفايات المستهدفة تبقى عبر الواجهة البرمجية لأنها لا تشير إلى كتل.
- D30: عنوان العقدة نص بقاعدة «آخر كاتب يفوز» وليس Y.Text؛ العناوين قصيرة.
- D31: بعد إنشاء DraftDocument لنسخة، تُرفض كتابة العقد والكتل والروابط عبر REST لتلك النسخة (`draft_is_live`)؛ الكاتب الوحيد هو التحويل من Yjs.
