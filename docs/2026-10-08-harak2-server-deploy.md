| البند | القيمة |
|---|---|
| التاريخ | 2026-10-08 |
| لمن | المالك، أول نشر على خادم |
| القرار | D97 |
| المرجع الكامل | دليل التشغيل `docs/2026-10-06-harak2-runbook.md`: النسخ الاحتياطي، والمراقبة، والتحديث، وحساب الطوارئ |

هذا الدليل يوصلك خطوة بخطوة إلى حراك يعمل على عنوان مثل `https://harak.example.com`، يدخله زملاؤك من أجهزتهم. الأمر `infra/deploy.sh` ينفّذ خطوات دليل التشغيل الأولى.

> **قبل أي بيانات حقيقية لعميل:** المسألتان المفتوحتان 2 و3 (حماية البيانات، وشروط المزوّد) لم تُحسما بعد (D94). جرّب مع زملائك بمحتوى تدريبي تجريبي، لا ببيانات متدربين أو مناهج عميل.

## 1. ما تحتاجه (تجهّزه مرة واحدة)

| البند | ماذا تختار | ما تحتفظ به لخطوة 3 |
|---|---|---|
| **خادم Linux** | Ubuntu 24.04 من أي مزوّد سحابي. دليل التشغيل يقدّر 4 أنوية و8 غيغابايت ذاكرة و50 غيغابايت قرص. لم يُقس أصغر من ذلك. يُفضَّل مركز بيانات في عُمان أو الخليج (المسألة المفتوحة 1) | عنوان IP الخادم، وطريقة الدخول إليه بـ SSH |
| **اسم نطاق** | نطاق تملكه، أو نطاق فرعي منه، مثل `harak.example.com` | — |
| **سجل DNS** | سجل `A` للاسم يشير إلى عنوان IP الخادم. يأخذ دقائق إلى ساعات | — |
| **مخزن ملفات S3** | «Object Storage» من مزوّد الخادم نفسه غالبًا، أو AWS S3. أنشئ **حاوية (bucket) خاصة**، ومفتاحي وصول لها وحدها | اسم الحاوية، وعنوان المزوّد (endpoint)، والمنطقة (region)، ومفتاحا الوصول |
| **بريد SMTP** (اختياري) | حساب إرسال من مزوّد بريد مؤسستك أو خدمة إرسال. بدونه لا تُرسل الدعوات، وتعطي زملاءك روابطهم بنفسك | عنوان SMTP واسم المستخدم وكلمة المرور |

## 2. تجهيز الخادم

ادخل إلى الخادم بـ SSH، ثم:

```sh
# Docker مع compose
curl -fsSL https://get.docker.com | sh

# الجدار الناري: SSH والويب فقط
sudo ufw allow OpenSSH && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw --force enable

# المشروع
git clone https://github.com/s141694-sketch/herak2.git
cd herak2
git checkout claude/phase-0-spike
```

المستودع خاص، فسيطلب `git clone` اسم المستخدم وكلمة مرور. اكتب اسم مستخدمك في GitHub، وفي كلمة المرور **رمز وصول شخصي** (GitHub ← Settings ← Developer settings ← Personal access tokens) له صلاحية قراءة هذا المستودع وحده.

## 3. الإعداد

```sh
infra/deploy.sh setup
```

يسألك عن:

1. **النطاق**: `harak.example.com`، بلا `https://`.
2. **مخزن الملفات**: اسم الحاوية، والعنوان (فارغ لـ AWS نفسها)، والمنطقة، ومفتاحي الوصول.
3. **البريد**: مثل `smtp+tls://user:password@smtp.example.com:587`. اتركه فارغًا إن لم يكن عندك.

ثم يكتب `backend/.env` بأسرار جديدة لا يقرؤه غيرك، ويطبع سطر `FIELD_ENCRYPTION_KEYS`. **احفظ هذا السطر في مكان آمن خارج الخادم**، مثل مدير كلمات المرور. بدونه لا تعود أسرار التحقق الثنائي من أي نسخة احتياطية.

## 4. التشغيل

```sh
infra/deploy.sh start
```

- أول مرة يبني الخدمات، وقد يستغرق 10 إلى 20 دقيقة.
- ثم ينتظر حتى تعمل كل الخدمات، ويشغّل فحص الدخان على `https://<نطاقك>`، ويحصل على شهادة TLS وحده.
- إن فشل بند فالرسالة تسمّيه. أشهر سبب: سجل DNS لم يصل بعد. انتظر، ثم أعد `infra/deploy.sh start`.

## 5. مؤسستك ومديرها

```sh
infra/deploy.sh organization
```

- يسأل عن اسم المؤسسة، ومعرّف قصير لها (مثل `vtc`)، وبريد مدير التدريب.
- يطبع رابطًا يختار منه المدير كلمة مروره. افتحه، واختر كلمة المرور، ثم ادخل.
- **فعّل التحقق الثنائي للمدير** فورًا: اسمك أعلى الصفحة ← التحقق الثنائي.

## 6. دعوة زملائك

من حساب المدير: **الأعضاء** ← **دعوة شخص**: البريد والدور، ثم **إرسال الدعوة**.

- **مع البريد:** تصل الدعوة إلى زميلك فيختار كلمة مروره.
- **بلا بريد:** على الخادم اطبع رابطه وأرسله له بنفسك:

  ```sh
  infra/deploy.sh link colleague@example.com vtc
  ```

ثم اتبعوا معًا السيناريو في `docs/2026-10-08-harak2-local-trial.md`، القسم 3، أو أدلة الأدوار.

## 7. بعد التشغيل

| متى | ماذا |
|---|---|
| كل يوم، وحده | نسخة احتياطية في الخادم نفسه. **انسخها خارج الخادم**: دليل التشغيل، القسم 6 |
| عند كل تحديث | `infra/deploy.sh update`: نسخة احتياطية، ثم آخر التزامات الفرع، ثم البناء والتشغيل والفحص |
| حين تريد الاطمئنان | `infra/deploy.sh status`: الخدمات وصحتها |
| أسبوعيًا | الجلسات المنتهية، والمساحة: دليل التشغيل، القسم 8 |

## 8. حدود

- مُختبر في CI على لينكس (مهمة «the server deployment script»)، بعنوان `localhost` ومخزن ملفات في الذاكرة مكان مخزن المزوّد. لم يُجرَّب على خادم حقيقي باسم نطاق حقيقي ولا مع مخزن مزوّد حقيقي ولا مع SMTP حقيقي.
- `infra/deploy.sh update` لم يُجرَّب في CI: يحتاج فرعًا يتبع المستودع، كما على الخادم.
- قبل فتح التجربة لعميل حقيقي، أكمل قائمة التحقق في دليل التشغيل، القسم 9.
